Does the fallback to the original Python code cost anything?  (investigated 2026-11-10 for 0.2.0)
Script: research/fallback_slowdown.py.  Machine: the reference laptop in BENCHMARKS.md.

Conclusion
----------
No. The "about 2x slower than rectpack" figure in the 0.1.0 notes (3.99 s against 1.85 s, 106.8 s against
59.8 s) was a measurement artifact. The fallback path makes 610 more Python function calls than plain rectpack
out of 8.87 million (0.007%), and takes the same time when the two are timed in alternation. The two numbers in
the 0.1.0 notes were not taken in alternation, on a machine whose speed for identical work changes by 2x to 4x
from one minute to the next (see session 1 below, and "Noise on this machine" in BENCHMARKS.md).

What is and is not established
------------------------------
Established: the fallback and the original run the same functions the same number of times, produce identical
output, and take the same time in every interleaved round, in both orders, in both sessions below.
Not established: what puts the machine into its slow state. In session 1 it started after about three seconds
of load and went away after 12 idle seconds, which points at a power or thermal limit. Session 2, an hour
later, showed no slow state at all, so that explanation is unconfirmed.
